Findings, ordered by impact
--------------------------
1. HIGH, confirmed: provider JSON can silently select different values than
   native JEV's parser, including accepting a missing canonical API field.

   cARL internal/assessment/policy.go:197-215 unmarshals provider/model/answer
   fields into Go structs. encoding/json matches field names case
   insensitively; CheckJSON only rejects exactly repeated keys
   (internal/assessment/json.go:52-66). Thus it does not reject aliases.
   MMMTAP phase2/adapters.py:352-366 instead reads exact "model", "answers",
   and "noul" keys.

   Reproduced against the current Go sources through a session-only overlay:
     "claim_0000_supported":{"noul":1,"NOUL":0}
   is accepted, with signal 0 and challenge_required. Native's exact-key
   extraction uses 1. Likewise "model":"expected","MODEL":"different" reports
   "different" in cARL; native reports "expected". A response containing only
   MODEL/ANSWERS/NOUL is accepted as no_challenge, despite having none of the
   canonical provider field names. ApplyPolicy is shared by live evaluation,
   offline evaluation, and replay (live.go:338,447; receipt.go:103), so replay
   repeats rather than detects this semantic drift.

   Consequence: malformed/ambiguous provider output can become policy success
   and undermine matched-mechanism comparability and reported-model evidence.
   This is not a claim that the real provider emits such output. The concrete
   remediation would be exact-key decoding and alias rejection at the API
   boundary, with negative tests shared with the native parser.

2. MEDIUM, confirmed: Python invents a transport-attempt count.

   phase2/adapters_v2.py:270-274 derives transport_attempts from whether
   mock_response was supplied, not the verified receipt. A guarded actual
   sibling invocation with JEVKEY blank returned credentials_unavailable,
   Go attempts=0/live_calls=0, but Python transport_attempts=1.
   Go's intended semantics are explicit in live.go:258-266: missing/invalid
   credentials cause zero transport attempts.

   Consequence: wrapper provenance contradicts its own preserved receipt and
   can overcount failed qualification attempts. Distinguish CLI invocation
   count from HTTP attempts; derive the latter from verified receipt data or
   retain an explicit unknown value when no receipt exists.

3. MEDIUM, confirmed: Path B usage metadata is retained in raw evidence but
   lost at the Python metrics handoff.

   phase2/adapters_v2.py:270-291 never sets Response.usage. A guarded mock
   evaluation with usage={input_tokens:123,output_tokens:45} preserved those
   exact values inside receipt.raw_response, while response.usage was None.
   phase2/engine.py:187-195 consequently reports all token counts and
   usage_raw as null. Native explicitly populates usage (adapters.py:429-431).

   Consequence: Path B's result metrics cannot support like-for-like usage
   analysis even when the provider supplies it. This is an extraction gap,
   not loss of the underlying bytes and not evidence of zero usage.

4. MEDIUM, confirmed: preparation failures bypass artifact preservation.

   phase2/adapters_v2.py:255-256 returns immediately with only processes.
   Artifact collection is later at :275-277; the surrounding temporary
   directory exits and removes the preparation's intent/request/failure files.
   Guarded invocation with request={} produced:
     error=unsupported_contract_or_preparation_failed
     provenance_keys=["processes"], has_preserved_artifacts=false
     stdout_bytes=0, stderr_bytes=0
   The process log still retains the child's stderr and exit status, so this
   is not total loss of failure information. It does lose the actual cARL
   first-attempt files that command.go:111-141,220-222 deliberately persists.
   Collect files before every return after staging starts, including failed
   prepare, without retrying.

Secondary replay limitations (confirmed behavior, lower impact)
-------------------------------------------------------------
* live.go:418-433 validates header names/TLS shape, not their full consistency
  with body/endpoint. A complete 173-byte successful response with sanitized
  Content-Length:["0"] and TLS.ServerName="not-the-recorded-endpoint.invalid"
  replayed successfully after receipt/anchor recomputation.
* receipt.go:125-142 reserializes the decoded v1 offline struct, rather than
  comparing against the original object. Removing live_calls, or inserting
  error:null into an otherwise successful receipt, still replays. The v2 live
  path has stronger required-field checks at live.go:369-377.
* Reusing exactly the same preparation in two explicit EvaluateLive calls
  produces two requests, each reporting attempts=1/live_calls=1. The transport
  promises one attempt per invocation, not global deduplication. CLI directory
  reservation protects a reused output directory, not a reused attempt ID
  across new directories (command.go:111). This is an operator responsibility
  / exactly-once limitation, not an observed automatic retry.

These mutation probes used newly computed anchors. They do NOT bypass an
independently retained original digest, forge provider authentication, or
establish that current live transport emits the contradictory receipts.
