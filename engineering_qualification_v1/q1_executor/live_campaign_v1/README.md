Implementation checklist

- Reuse the sole SQLite reservation/journal/receipt engine; bind complete packets,
  provider routes, model contracts, runtime binaries and parser/compiler hashes.
- Preserve the original worker/bootstrap and frozen validators byte for byte.
  Deliver the governing packet on every generator turn; controls receive no
  challenge, and challenge policy never becomes governing authority.
- Use the actual HTTPS broker, incremental exact raw entity custody, explicit
  trust, TLS name verification, no DNS/proxies/redirects/retries/fallbacks, and
  nftables default-drop plus postconnect socket/exec denial.
- Retain `JEVKEY` only in hardened trusted-launcher memory for serial dispatch;
  per-broker readiness/PID authentication precedes release. Wipe mutable copies
  at handoff/session end. No claim of universal CPython string erasure or
  protection from root/namespace administrators. No key is stored or hashed.
- Bind one authoritative custody directory/database inode per deployment and
  hold a deployment-wide flock. Copies cannot execute; archival reconstruction
  stays read-only. This does not provide cross-host or operator rollback defense.
- Consume empty-claim and cARL-inadmissible quotation inputs without credential
  release or a POST; censor their dependent positions without repair/replacement.
- Invoke the frozen cARL compiler for each new cARL request. Read-only replay
  checks every captured preparation field against its exact input/parent and the
  sealed actual compiled-policy snapshot; it does not recompile prior requests
  in every fresh broker. This avoids approaching the supervisor deadline as the
  journal grows. Rules, compiler and scientific semantics are unchanged.
- Fix bootstrap ACK/probe ordering before credential-readiness journal commits;
  retain the original SQLite I/O error if SQLite already rolled back.
- Reuse the already decoded broker receipt projection within each complete
  read-only verification, and select supervisor records by position in SQLite.
  Profiling found repeated whole-journal decoding dominated startup. Every event,
  raw prefix, binding and transition is still audited; timeouts were not enlarged.

Exact proposed inputs, not approved research evidence

The three source byte strings come from the existing integration pilot:
documentation-only wording, INFO token logging, and an unauthenticated metadata
endpoint. They are authored stimuli with provisional role assignments, not
authenticated diffs, deployed-state evidence or adjudicated ground truth.
`source-bundle.json` is an explicitly new byte collection of those preserved
strings, not a fabricated historical archive or Git attestation.

The governing packet is the **verbatim existing fictional RD05 policy**, whose
own provenance denies PI/organisational authority. Its E-DIFF/E-TEST obligations
are not fulfilled by these short source strings. PI must either select this
policy/stimulus combination explicitly with its insufficiency implications or
supply sufficient packets and an applicable policy. No RD05 adjudication changes.
The challenge packet copies the existing cARL packs. The default applied pack
uses 0.5 thresholds; the preserved cautious profile contains different thresholds
and is not silently activated. None of these thresholds is newly approved.
Continuation after `no_challenge` and continuation of independent branches after
failure are explicit **proposals requiring PI approval**, not implementation
defaults authorised for research.

provider executions have no established bound. Requests/entities are limited

supervision to 25 seconds. These bound local capture/waiting, not remote work or
billing. Token/spend ceilings remain null. Fixture usage is not a live forecast.
An expected live token total or dollar exposure cannot responsibly be supplied
without account/tariff and natural-response evidence.

custody. Recovery uses the same authoritative directory: outstanding reservations
become interrupted; never retransmit, copy/rebind the database, or replace an
