# Separately authorized live requalification

**STOP: this package does not authorize live calls. All three generators remain
blocked. Do not run live qualification under the current seal.** The procedure
below defines prerequisites for a later, separately approved task; it is not an
instruction to start that task now.

1. **Resolve preventive isolation first.** An approved implementation must prevent
   unauthorized tool dispatch, inherited instruction/configuration/session
   reuse, host-file access, process execution by model tools, credential
   disclosure, hidden client retries and non-provider network egress. Codex's
   advertised internal routes and Copilot's observed six-POST error behavior
   must be addressed, not merely watched. If this needs a broker or a changed
   experimental assumption, obtain explicit design/methodology approval first.
2. **Approve instruments and disclosure.** The PI must approve the exact prompt,
   question, evidence/assessment schema, roles, policy thresholds, model/version
   policy, raw-data disclosure and retention rules. Preserve original scoring,
   both E3 orders, the two-neutral-turn C3 and all 135 input identities. Native
   JEV and Path B use separate evaluations of the same underlying SystemOne
   request semantics; policy outcomes need not agree.
3. **Produce a new implementation-bound proposal.** Pin the corrected CLI and
   helper/runtime closure, explicit provider endpoints, transport configuration,
   Path B build receipt and instrument snapshots. Run complete offline suites,
   matched parser fixtures, preventive positive/negative controls and full
   nonempty mock chains after the last implementation change. Seal a new plan
   with new identities. Do not modify v2, v3, rejected v4 or this v5 evidence.
   Removing the current hard block requires a reviewed source change, not a
   configuration checkbox.
4. **Obtain specific live authorization.** Approval must identify the sealed
   implementation/plan, adapter and exact requested model, permitted inputs,
   endpoint/auth route, at-most-one HTTP attempt per reserved diagnostic,
   timeout and call budget, operator, disclosure scope and stop conditions.
   It must explicitly exclude a pilot/full experiment. Confirm credentials
   out of band; do not put them in prompts, command arguments, reports or
   source control.
5. **Reserve before preparation.** Use the current qualification entry point and
   its fixed workspace registry. The attempt must be reserved before parent
   validation, request preparation or credential/process staging. A new output
   directory is not permission to reuse the same plan/adapter identity. For any
   intentional subsequent attempt, obtain a linked new plan/authorization with
   a reason and the previous reservation hash. Preserve failed and incomplete
   attempts. Do not fall back to legacy CLI interfaces to evade a block.
6. **Qualify the generator before adversaries.** Independently review an actual
   valid nonempty B0, exact source/manifest bindings, served-identity evidence,
   tool/HTTP counts, raw streams, session isolation, credential handling and
   absence of unintended source disclosure. BYOK loopback success is not proof
   of the authenticated route. A generator failure stops dependent qualification.
7. **Qualify native JEV and Path B separately.** Both require the same actual,
   valid, qualified nonempty B0 parent with complete checkpoint hashes. Verify
   exact matched native request bytes, fixed SystemOne endpoint, bounded
   non-retrying transport, response/usage integrity and no credential echo.
   Keep requested and reported identities distinct; obtain independent served
   identity evidence rather than promoting an untrusted response string.
   Verify Path B's CLI checksum anchors, prepared/body/receipt links and
   deterministic offline replay.
8. **Review first-attempt outcomes before another action.** Stop on any unknown
   execution state, retry, tool route, egress deviation, malformed/missing
   artifact, schema mismatch, identity discrepancy or cleanup failure.
   Unknown execution is not zero execution. Do not reissue inference to repair
   evidence. Retain the private raw artifacts and original reservation and
   record an explicit unresolved outcome.
9. **Keep experimental approval separate.** Even successful diagnostics remain
   unqualified until independent raw-evidence review and instrument approval.
   They do not unlock the experiment engine. A separately reviewed new
   gate/plan and explicit pilot authorization are required before any pilot;
   full-study authorization is another decision.

The reference artifact is `v5/execution_plan_v5.json`, with instruments at
`v5/instruments/manifest.json`. The final report and checksum manifest provide
their exact hashes. They are prerequisites for review, not a transferable
authorization to use different software, providers or source bytes.
